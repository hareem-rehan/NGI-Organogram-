# Defect Register — Release Hardening (Phase 13)

Tracks every defect found during Phase 13 hardening, from baseline verification through final sign-off. See `docs/PROJECT_SPEC.md`/`docs/phase-reports/PHASE_13_RELEASE_HARDENING.md` for context.

## Severity Definitions

**Critical** — blocks release, no exception: authentication bypass; cross-company data exposure; destructive data corruption; secret exposure; arbitrary code execution; unrecoverable hierarchy corruption; complete production-blocking failure.

**High** — blocks release unless explicitly accepted by an authorized stakeholder with documented rationale: authorization bypass; persistent XSS; major hierarchy/assignment integrity failure; imports partially corrupting data; exports exposing another company's data; last-admin protection failure; audit records containing secrets; a major feature unusable for its intended role.

**Medium** — requires resolution or a documented release decision: an important workflow failure with a workaround; a significant accessibility issue; a performance issue affecting realistic data; a misleading metric or visual state; incomplete error recovery.

**Low** — may enter Known Issues without blocking release: a cosmetic issue; a minor content problem; a non-blocking usability improvement.
