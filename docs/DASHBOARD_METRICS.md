# Dashboard Metrics — Dynamic Organogram Manager

Authoritative definition of every metric and data-quality warning on the Company Overview dashboard (Phase 7). Every number the dashboard shows must trace back to a definition here — if a metric on screen doesn't match this file, the file wins and the code has a bug (`CLAUDE.md` §1.13/1.16).

Conventions used throughout this file:

- **Effective date** — the server's current calendar date at request time, captured once per request. No historical or future-dated query exists (`docs/DECISIONS.md` P9).
- **Occupied / vacant** — derived from `PositionAssignment`, exclusive-end (`startDate <= today AND (endDate IS NULL OR endDate > today)`), the exact convention fixed in Phase 6 (`docs/DECISIONS.md` A18). Never a stored flag.
- **Organizational level** — always read from `Position.organizationalLevel` as already computed by `lib/services/hierarchy.service.ts`. The dashboard never recomputes it independently; it only aggregates/counts the stored value.
- **Job Grade vs. Organizational Level** — never conflated. No dashboard metric derives one from the other (`docs/DOMAIN_MODEL.md` principle 8).
- **Active** (department/position) means `status = ACTIVE`. **Active** (employee) means `employmentStatus = ACTIVE`. These are three independent status fields on three independent entities — a metric name never implies one status controls another.
- **Company scoping** — every query below is implicitly `WHERE companyId = :sessionCompanyId`, taken only from the authenticated session (`getAuthorizedCompanyContext()`), never from client input.
- **Empty-state value** — every count below is `0`, not `null`/"N/A"/an error, when nothing matches. Zero is valid data (Phase 7 Step 12).

## F. Vacancy Rate

**Definition:**

```
vacancy rate (%) = vacant active positions / total eligible active positions × 100
```

- **Total eligible active positions** = active positions (`status = ACTIVE`) belonging to an active department (`department.status = ACTIVE`). Planned and inactive positions are never in the denominator or numerator. A position in an inactive department is excluded from both, since its department is already excluded from the main summaries (default: "inactive departments are excluded from main summaries").
- **Division by zero**: if total eligible active positions is `0`, the rate is `null` ("not applicable" — shown as "—", never `0%`, `NaN`, or `Infinity%`), never crashes.
- **Rounding**: rounded to the nearest whole percentage point (`Math.round`), consistently, for display. The exact unrounded count (vacant / eligible) is always shown alongside the percentage so nothing is lost to rounding.
- **Help text**: the dashboard shows the formula and both raw numbers next to the percentage, not just the bare "%".

## I. Privacy Boundaries

The dashboard never displays: salary, private contact information (personal address, phone), SSO/identity-provider details, access tokens, or any employee's authentication role. Employee **names** are never shown on the dashboard in Phase 7 — every employee-related number is a count or an aggregate; a data-quality warning's "safe link" navigates to the existing, already-permission-gated Employees/Positions list rather than embedding a name or other personal field directly in the dashboard payload.

## J. Empty and Partial States

- **Zero is valid data.** Every count metric's empty state is `0`, never an error banner, never omitted as if it were missing.
- **No root position yet** (brand-new company, nothing created): shown as a specific, named state ("No root position yet — create the first position to begin your organization chart"), not folded into a generic "no data" message, since it is the one condition that meaningfully blocks the org chart itself.
- **Partial-section failure**: each of the dashboard's independent sections (summary cards, department table, warnings) is computed by its own try/caught call; if one section's underlying query throws, that section renders "This section is temporarily unavailable" and every other section still renders normally with its real data — never a single exception blanking the whole page, and never silently omitted without the honest label.

## K. Refresh/Caching Behavior

No caching exists in Phase 7 — every load is a live query (see the phase report's "Caching and Invalidation Plan"). The "Last refreshed" timestamp is simply the request's own server time.

## L. Known Limitations

- Deactivating a position does not currently end any assignment still open on it (a pre-existing Phase 5/6 behavior, not introduced by Phase 7) — this is exactly why "active assignment connected to inactive position" is a real, useful warning rather than a purely defensive one.
- Timezone is displayed but does not shift the effective-date boundary (see the phase report's "Company-Timezone Behavior").
- No dashboard filters (department/status) are implemented in Phase 7 — the phase's own instructions mark filters as optional/approved-if-supported, and no prior decision confirmed them; the dashboard shows the whole company, and every count links out to the already-filterable Departments/Positions/Employees pages instead.
