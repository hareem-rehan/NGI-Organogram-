# Environment Variable Matrix — Phase 14

Derived directly from the app's own real, already-implemented, Zod-validated environment schema (`lib/env.ts`'s `serverEnvSchema`/`publicEnvSchema`), not invented for this phase. `lib/env.server.ts` and `lib/env.public.ts` already parse and validate these at module-load time — an app instance with a missing or invalid required variable fails to start rather than running with an unsafe default, satisfying this phase's "startup must fail for missing critical variables" requirement natively, with no new code needed. No secret value appears in this document — see `.env.example` for the full annotated template with safe placeholder values.

## Application

| Variable               | Required                                 | Notes                                                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`             | No (defaults `development`)              | Set to `production` by the hosting platform automatically in virtually every case (Vercel sets this itself for production/preview builds) — not something to hand-set in most setups.                                                                                                                                                  |
| `NEXT_PUBLIC_APP_NAME` | Yes                                      | Browser-safe (bundled to the client). Display name only.                                                                                                                                                                                                                                                                               |
| `LOG_LEVEL`            | No (defaults `info`)                     | One of `debug`/`info`/`warn`/`error` (`lib/logger.ts`). Production should stay at `info` or `warn` — never `debug`, which is more likely to include verbose payloads (Step 12's "production log level must not expose debug payloads").                                                                                                |
| Application base URL   | **Not a separate variable in this app.** | Auth.js derives the callback URL from the incoming request's own host, with `AUTH_TRUST_HOST` (below) governing whether that's trusted behind a reverse proxy/non-standard host. Verify this resolves correctly once a real staging/production domain exists — flagged as a staging-deployment verification item, not assumed working. |
| Application version    | **Not an environment variable.**         | `lib/version.ts`'s `getAppVersion()` reads `package.json`'s own `version` field directly — already satisfies "application version traceable" without a separate var to keep in sync.                                                                                                                                                   |

## Authentication (Company SSO — provider-neutral OIDC)

Confirmed provider for this deployment: **Google Workspace**. The app itself has no Google-specific code — it speaks standard OIDC to whatever issuer these variables point at (`docs/adr/0010-authjs-provider-neutral-oidc.md`), so switching providers later is a configuration change, not a code change.

| Variable                      | Required                               | Notes                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTH_SECRET`                 | Yes (32+ chars)                        | Session/cookie signing key. Rotate via the platform's secret manager, never by editing a file in the repo.                                                                                                                                                                                                                                                                                        |
| `AUTH_TRUST_HOST`             | No                                     | Set `"true"` if deployed behind a reverse proxy or on a non-default host — verify during staging deployment whether Vercel's own edge network requires this.                                                                                                                                                                                                                                      |
| `AUTH_OIDC_ISSUER`            | Yes                                    | For Google Workspace: `https://accounts.google.com` (Auth.js discovers endpoints via `<issuer>/.well-known/openid-configuration`).                                                                                                                                                                                                                                                                |
| `AUTH_OIDC_CLIENT_ID`         | Yes                                    | From the Google Cloud Console OAuth 2.0 Client ID, once one is registered — not yet created.                                                                                                                                                                                                                                                                                                      |
| `AUTH_OIDC_CLIENT_SECRET`     | Yes                                    | From the same registration. Never logged, never sent to the browser.                                                                                                                                                                                                                                                                                                                              |
| `AUTH_ALLOWED_TENANT_ID`      | No                                     | Google Workspace's equivalent tenant-restriction claim (`hd`, the hosted-domain claim) — this app's tenant-claim mechanism (`AUTH_OIDC_TENANT_CLAIM`, below) needs to be pointed at `hd` for Google, since the schema's own default (`"tid"`) is Microsoft Entra ID's claim name, not Google's. **Verify this explicitly during SSO configuration — do not assume the default works for Google.** |
| `AUTH_OIDC_TENANT_CLAIM`      | No (defaults `"tid"`)                  | **Must be overridden to `"hd"` for Google Workspace** per the note above.                                                                                                                                                                                                                                                                                                                         |
| `AUTH_ALLOWED_EMAIL_DOMAINS`  | Yes                                    | The real Google Workspace domain(s), once known — not yet provided.                                                                                                                                                                                                                                                                                                                               |
| `AUTH_PROVIDER_NAME`          | No (defaults `"Company Account"`)      | Display label only, e.g. `"Sign in with Google Workspace"` — never a hard-coded vendor name in source, already true today.                                                                                                                                                                                                                                                                        |
| `AUTH_AUTO_PROVISION_VIEWERS` | No (defaults `false`, deny-by-default) | Leave `false` for production unless explicitly decided otherwise — an allowed-domain user with no provisioned account should land on an access-request page, not silently gain VIEWER access.                                                                                                                                                                                                     |

## Storage (CSV imports, generated PDF/PNG exports)

**Not applicable — no separate storage service exists in this app's architecture.** Uploaded CSV bytes (`ImportJob.rawFile`) and generated export files (`ExportJob.generatedFile`) are stored directly in PostgreSQL for a bounded retention window, a documented Phase 10/11 decision made because this app has no object-storage integration (`docs/DECISIONS.md`). There is no bucket/account/region/endpoint to configure. Retention is governed by code constants (`IMPORT_RETENTION_DAYS`, `EXPORT_RETENTION_DAYS`), not environment variables — see `docs/CSV_IMPORT_GUIDE.md`/`docs/ORGANOGRAM_EXPORT_GUIDE.md`. If a future phase moves storage to a real object-storage service, this section will need real variables at that time.

## Jobs (background worker / scheduled cleanup)

**Not applicable — no background-job queue or scheduler exists in this app's architecture.** Import/export execution is synchronous within one HTTP request (no queue, no worker process); expiry/cleanup is lazy — enforced on the next request that touches a stale job, not by a scheduled sweep (`docs/DECISIONS.md`, repeated across Phases 10–13). There is no job-timeout/retry-limit variable to configure because there is no retry mechanism to configure — a failed import/export simply reports `FAILED` to the requesting user. If a future phase adds real background processing, this section needs real variables at that time.

## Observability

**Not applicable — no external monitoring/tracing/error-reporting service is integrated today.** The app writes structured logs via `lib/logger.ts` (respecting `LOG_LEVEL` above) to stdout, which Vercel's own platform-level log capture picks up automatically once deployed there — no separate monitoring SDK/API-key variable exists in the current codebase. Whether the user wants a dedicated APM/error-tracking tool layered on top is one of the still-open decisions in `docs/DEPLOYMENT_DECISIONS.md`.
